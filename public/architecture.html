Engineering architecture 面向工程学习者的系统拆解

一层一层，看懂口语评估系统。

Design principles / 设计原则

让可靠性先于智能。

The architecture is shaped as much by failure handling and data boundaries as by the evaluation model itself.

01

先保存，再计算

用户回答先获得持久落点，耗时的媒体处理与模型评估随后异步进行。

Durable before expensive
02

先证据，后评分

转写、语速、停顿和画面分别进入明确的评分维度，不用单一信号概括全部表现。

Evidence before score
03

有边界地并行

队列、准入和并发控制共同保护服务稳定性，拥塞不会转化为无限增长的等待。

Bounded asynchronous work
04

默认保持私有

身份、同意和所有权贯穿题目、回答与历史；原始媒体不进入公开页面。

Private by default

Evaluation pipeline / 评估流水线

八个阶段，一条证据链。

选择任一阶段，查看它接收什么、产生什么，以及为什么这样拆分。 Choose a stage to inspect its input, evidence, and design rationale.

01 / Capture

在浏览器中完成一次完整回答。

采集发生在用户设备上。浏览器持续确认所需媒体轨道是否仍然有效，并把有效回答整理成一个待提交单元。

输入 / Input

准备好的任务、用户设备权限、实时音视频。

产出 / Output

完整回答、媒体类型，以及设备在录制期间未中断的校验结果。

Design choice

先把采集边界处理干净，后面的转写和评分才有稳定、可验证的输入。

02 / Durable intake

先确认归属，再接收昂贵工作。

提交必须对应到当前用户拥有的任务。系统为提交建立幂等引用，并把回答与处理任务一起保存到持久边界。

输入 / Input

回答文件、任务引用、提交标识与当前身份。

产出 / Output

可恢复的持久任务、处理状态，以及重复提交时的既有结果。

Design choice

只有当回答已经安全落盘，系统才把“已接收”告诉用户并启动后续处理。

03 / Normalize media

把不同来源整理成统一、可验证的媒体。

服务端验证文件是否可读、是否包含可评估的声音，并统一容器格式。可用视频还会提取独立音频，供后续证据阶段使用。

输入 / Input

浏览器录制或独立上传的受支持媒体。

产出 / Output

规范化后的私有回答、提取音频，以及媒体元数据。

Design choice

规范化让“能否评估”在进入模型之前就有确定答案，也避免把格式差异误当成表达差异。

04 / Transcribe

把可评估的语音变成结构化文本证据。

长回答按顺序分段转写，短暂失败可以重试，并保留兼容性回退路径。转写只负责表达内容，不直接给学习者评分。

输入 / Input

规范化的音频、回答语言和任务上下文。

产出 / Output

有序转写文本，以及用于判断可懂度的辅助线索。

Design choice

转写与评分分开，让语言内容、表达节奏和视觉表现可以使用各自最合适的证据。

05 / Measure delivery

用时间结构补充“听起来的感受”。

系统从音频中计算时长、静音、停顿、词数和语速等指标，使流利度不只依赖文字层面的印象。

输入 / Input

提取后的音频与转写文本。

产出 / Output

停顿结构、说话速度、词数和相关时长的可解释指标。

Design choice

节奏指标与转写证据相互校验，而不是用一个“流利度”标签替代可观察的过程。

06 / Sample frames

只为镜头表达抽取必要画面。

摄像头回答会按时间覆盖抽取少量画面，用于观察姿态、取景、面部参与度与干扰动作。纯音频回答不会伪造视觉证据。

输入 / Input

规范化后的视频回答，或明确无画面的音频回答。

产出 / Output

有代表性的抽样画面；没有视频时则标记镜头表达不可评估。

Design choice

视觉评分只关注沟通行为，不评价外貌；音频模式会自动排除并重新分配视觉维度。

07 / Structured scoring

让每个分数都能回到证据。

评估请求同时携带题目、回答背景、版本化评分标准、转写文本、节奏指标和可用画面。输出被规范为固定维度、总结、优势和改进建议。

输入 / Input

任务上下文、评分标准，以及前序阶段产生的全部有效证据。

产出 / Output

六维评分、总分、摘要、优势、改进方向与评分标准版本。

Design choice

评分维度、证据来源和权重由版本化标准定义，模型输出必须回到这套结构，而不是自由生成一段结论。

08 / Persist & explain

评估可以失败，回答不能消失。

处理结果被写回持久记录。即使后续评估失败，原始回答仍会保留，失败状态也会被记录下来，而不是让用户重录。

输入 / Input

原始回答、处理产物、结构化评分或明确的失败状态。

产出 / Output

拥有者可见的历史记录、分项反馈，以及可回看的私有原始回答。

Design choice

历史页读取的是所有权过滤后的记录；失败是状态，不是丢弃用户内容的条件。

Reliability / 可靠性

分数可以等待，回答不能丢失。

用户体验看起来只是一次上传，背后却是一套把“已接收”和“已完成”分开的系统。

01

持久确认

提交得到确认前，回答和处理任务已经进入可恢复边界。

02

断点可恢复

任务记录阶段进度，失败可以重试；进程中断后仍能继续未完成工作。

03

压力有上限

准入、排队和并发上限共同保护系统，不用无界等待换取表面可用。

Fast path 接收回答

验证归属 → 持久保存 → 返回任务引用

→
Durable work 完成评估

Ownership & privacy / 所有权与隐私

反馈属于回答它的人。

Identity and consent are part of the product architecture, not an afterthought around it.

01

版本化同意

生成题目和处理回答前确认当前隐私同意；政策版本与同意状态可追溯。

02

所有权边界

题目、回答、历史和媒体请求都按当前身份过滤，记录不因知道链接而跨人可见。

03

原始媒体私有

公开页面不会直接暴露用户的录制目录。视频和音频默认只供所属用户回看。

04

纯音频也完整

不开启摄像头时，系统保留音频转写、节奏和语言证据，并明确不评估镜头表达。
